# ADR-0004 — The simulator is built in-project, not supplied to it

**Status:** accepted · **Date:** 2026-09-09 · **Supersedes in part:** ADR-0002

## Context

ADR-0002 was written on the assumption that the parameterised range-Doppler simulation
function would be supplied by the research group, and the whole repository was arranged
around that: an interface, a stand-in behind it, and `adapter.py` as the one file that
would change on handover. At the Team B meeting on 2026-09-09 the co-supervisor confirmed
the opposite — the data is to be generated by this project. There is no function to
integrate.

This is not a delay, it is a change of kind. The dominant *schedule* risk disappears: no
handover to wait for, no unknown parameterisation to discover, and M2 can start
immediately. In its place comes a *validity* risk. A signal model supplied by a radar
group is a premise the thesis may reasonably assume; a signal model written by the author
of the detectors is a claim the thesis has to defend.

## Decision

The simulator is part of the apparatus and is built, documented, validated and released
with the rest of the repository.

1. **The interface is unchanged.** `SimConfig` in, `SimBatch` out, `RDMapSimulator` as the
   protocol. This is what makes the change cheap: nothing downstream ever depended on
   where a `SimBatch` came from.
2. **`adapter.py` is deleted.** It existed only to translate an external function, and its
   `group` simulator name goes with it. The name `prdsim` is reserved for the validated
   simulator and raises `NotImplementedError` until it exists, so `configs/protocol/
   full.yaml` fails loudly rather than quietly falling back to the development generator.
3. **`stub.py` is renamed in role, not in file.** It is the development generator: it
   proves the pipeline and nothing else, and its output stays unreportable.
4. **The model is specified before it is written.** Every component — receiver noise, the
   ambiguity-function response of a point target, the zero-Doppler direct-path ridge left
   by cancellation, and extended clutter — is justified against the passive-radar
   literature, and the definition of SNR is stated explicitly, because the "Pd vs SNR"
   curve means nothing without it.
5. **Validation is a gate on M2, not a footnote.** Three checks are run and reported with
   the frozen protocol:
   * the target-free noise floor against the distribution it is supposed to follow;
   * a single target's peak against the SNR it was generated at;
   * CA-CFAR's measured Pfa on target-free maps against the Pfa its multiplier is
     designed for (ADR-0001, eq. for α).

   The third is the load-bearing one. If measured and design Pfa agree, the background
   really is the distribution the classical detectors assume, and the CFAR baselines are
   being given a fair test — which is the control the whole comparison rests on.
6. **Circularity is handled in the open.** The generator and the detectors have the same
   author, so in-distribution results alone cannot separate a detector that learned the
   physics from one that learned the generator. The shift-test set lies entirely outside
   the training grid and is reported separately; a gain that does not survive there is
   reported as an artefact of the generator, not as a finding.

## Consequences

* **Cost.** Building and validating the simulator is now project work, scheduled inside
  M2. It was previously assumed to cost nothing.
* **Schedule.** The project's top risk stops being "will it arrive" and becomes "is it
  faithful". Work can begin at once; there is no external party to wait on or chase.
* **Reproducibility improves.** The generator can be released with the benchmark, so a
  third party can regenerate every reported number from a config and a seed. The old plan
  could only release the benchmark *around* a simulator it was not allowed to publish.
* **Risk register.** Old RSK-01 (non-delivery) and RSK-02 (unexpected parameterisation)
  are gone. The identifiers are reused for model fidelity and for author circularity.
  RSK-05 is narrowed to regime shift so that it does not restate RSK-01.
* **Scope statement.** The simulator is an instrument, not a claim: it implements an
  established signal model and is offered as a documented test bench, not as a
  contribution to passive radar simulation. The thesis says so explicitly.
